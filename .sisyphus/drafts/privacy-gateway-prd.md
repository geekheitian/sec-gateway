# Privacy Gateway - 产品需求文档 (PRD) v1.0

> 本文档定义 privacy-gateway 产品的功能需求、用户故事和技术约束。

---

## 1. 产品概述

### 1.1 产品定位

**产品名称**: Privacy Gateway  
**产品类型**: 本地隐私保护代理 (Local Privacy Proxy)  
**核心定位**: 保护终端用户与大模型之间的敏感数据，确保敏感信息只在本地流转。

### 1.2 目标用户

| 用户类型 | 描述 | 典型场景 |
|---------|------|---------|
| **个人开发者** | 使用Claude Code/GPT等AI工具处理代码 | 担心API Key泄露 |
| **技术团队** | 团队成员共用AI服务 | 需要统一隐私策略 |
| **企业用户** | 受监管行业使用AI | HIPAA/GDPR合规 |

### 1.3 核心价值

```
用户输入: "帮我分析这段代码，API Key是sk-abc123..."
                    ↓
         [Privacy Gateway本地处理]
                    ↓
LLM收到: "帮我分析这段代码，API Key是[HASH_xxx]..."
                    ↓
LLM返回: "这个API Key是OpenAI的格式..."
                    ↓
用户收到: "这个API Key是sk-abc123..."
```

**关键保证**: 
- 原始敏感数据 **永远不离开本地**
- 发送给LLM的是 **脱敏后的数据**
- 返回结果中 **自动恢复** 原始数据

## 2. 用户故事

### 2.1 核心用户故事

#### US-1: 开发者保护API Key

| 项目 | 内容 |
|------|------|
| **ID** | US-1 |
| **标题** | 作为开发者，我希望AI帮我处理包含API Key的代码，而不泄露这些Key |
| **背景** | 我经常需要向AI发送代码片段，这些片段中包含我的API Key |
| ** Acceptance Criteria** | 1. API Key自动被检测并脱敏<br>2. 脱敏后Key仍保持可识别格式<br>3. AI响应中的Key引用会被还原 |
| **示例输入** | "这个函数使用API Key `sk-abc123XYZ` 调用服务" |
| **预期输出** | "这个函数使用API Key `[OPENAI_KEY_abc123]` 调用服务" |

#### US-2: 用户保护身份证号

| 项目 | 内容 |
|------|------|
| **ID** | US-2 |
| **标题** | 作为用户，我希望AI帮我处理包含身份证号的文档，而不泄露身份证信息 |
| **背景** | 我需要AI帮我分析和处理一些官方文档，这些文档包含我的身份证号 |
| **Acceptance Criteria** | 1. 身份证号自动被检测并脱敏<br>2. 脱敏后保持18位数字格式<br>3. AI能理解这是身份证号（格式保留） |
| **示例输入** | "我的身份证号是110101199001011234，请帮我xxx" |
| **预期输出** | "我的身份证号是[MASK_110101199001011234]，请帮我xxx" |

#### US-3: 团队统一隐私策略

| 项目 | 内容 |
|------|------|
| **ID** | US-3 |
| **标题** | 作为团队负责人，我希望团队所有成员的AI请求都经过统一的隐私策略 |
| **背景** | 我的团队有5个人，大家都在用不同的AI工具，我想统一管理 |
| **Acceptance Criteria** | 1. 可以配置统一的脱敏规则<br>2. 规则变更自动生效（无需重启）<br>3. 可以查看脱敏统计 |
| **配置示例** | ```yaml<br>pii:<br>  id_card: fpe<br>  phone: fpe<br>  api_key: hash<br>``` |

### 2.2 次要用户故事

#### US-4: 查看审计日志

| 项目 | 内容 |
|------|------|
| **ID** | US-4 |
| **标题** | 作为安全负责人，我希望查看AI请求的审计日志，证明没有敏感数据泄露 |
| **背景** | 审计需要证明我们向LLM发送的数据已经过脱敏处理 |
| **Acceptance Criteria** | 1. 可以查看历史请求记录<br>2. 日志中不包含原始敏感数据<br>3. 日志显示脱敏统计 |

#### US-5: 流式响应处理

| 项目 | 内容 |
|------|------|
| **ID** | US-5 |
| **标题** | 作为用户，我希望流式AI响应中的敏感信息也能被正确处理 |
| **背景** | 我使用流式API，AI一个字一个字地返回，流式响应中的敏感信息也应该被处理 |
| **Acceptance Criteria** | 1. SSE流式数据中的令牌被正确恢复<br>2. 恢复延迟 < 50ms<br>3. 流式体验不受影响 |

### 3.2 PII类型支持

#### MVP (P0)

| PII类型 | 检测方式 | 脱敏策略 | 示例 |
|---------|---------|---------|------|
| 中国身份证号 | Regex (18位+校验) | FPE | `110101199001011234` → `XXXXXX19900101XXXX` |
| 手机号 (大陆) | Regex (11位) | FPE | `13812345678` → `138****5678` |
| 邮箱地址 | Regex | Replace | `user@email.com` → `[EMAIL]` |
| API Key | Regex + Entropy | Hash | `sk-abc123` → `[HASH_xxx]` |
| API Secret | Regex + Entropy | Hash | `secret123` → `[HASH_xxx]` |
| AWS Access Key | Regex | Hash | `AKIAIOSFODNN7EXAMPLE` → `[HASH_xxx]` |
| AWS Secret Key | Regex + Entropy | Hash | `wJalrXUtnFEMI/K7MDENG/bPxRfiCY` → `[HASH_xxx]` |
| GitHub Token | Regex | Hash | `ghp_xxx` → `[HASH_xxx]` |

#### v1.0 (P1)

| PII类型 | 检测方式 | 脱敏策略 |
|---------|---------|---------|
| 信用卡号 | Regex (Luhn校验) | FPE |
| IP地址 | Regex | Replace |
| JWT Token | Regex | Hash |
| 数据库连接字符串 | Regex + Entropy | Hash |
| 护照号 | Regex | FPE |
| 多国手机号 | Regex | FPE |

### 3.3 脱敏策略详解

| 策略 | 说明 | 适用场景 | 示例 |
|------|------|---------|------|
| **FPE** | 格式保留加密，保持原始格式和长度 | 需要LLM理解数据结构 | `110101199001011234` → `782345678901234567` |
| **Hash** | 单向哈希，不可逆 | 不需要恢复的敏感数据 | `sk-abc123` → `3a2f1b...` |
| **Replace** | 直接替换为占位符 | 简单脱敏 | `user@email.com` → `[EMAIL]` |
| **Mask** | 部分掩码，保留部分信息 | 需要保留部分可读性 | `13812345678` → `138****5678` |

### 3.4 非功能需求

#### 3.4.1 性能需求

| 指标 | 目标值 | 说明 |
|------|--------|------|
| P99延迟 | < 100ms | 包含网络开销 |
| 无PII请求延迟 | < 5ms | 透传开销 |
| 单PII检测+脱敏 | < 10ms | 检测+脱敏 |
| 内存占用 | < 50MB | 空闲状态 |
| 并发连接 | 100+ | 同时处理的请求数 |

#### 3.4.2 安全需求

| 需求 | 说明 |
|------|------|
| 数据本地处理 | 原始敏感数据不离开进程内存 |
| 无持久化 | 敏感数据不写入磁盘 |
| 内存清除 | Session结束后清除敏感数据 |
| 日志脱敏 | 日志中不记录原始敏感数据 |

#### 3.4.3 兼容性需求

| 需求 | 说明 |
|------|------|
| OpenAI API | 兼容 Chat Completions API |
| Anthropic API | 兼容 Messages API (v1.0) |
| Google API | 兼容 Gemini API (v1.0) |
| 本地LLM | 兼容 Ollama 等本地API (v1.0) |
| Docker | 支持 Docker 部署 |
| Linux/Mac/Windows | 支持主流操作系统 |

### 5.2 数据流

```
1. 请求入口
   客户端 → POST /v1/chat/completions
   Content-Type: application/json

2. 请求拦截
   解析JSON → 提取 messages.content

3. PII检测
   Regex检测 → Entropy检测 → 收集PIIMatch列表

4. 脱敏处理
   For each PIIMatch:
     - 生成令牌
     - 存储映射到隐私金库
     - 替换原文本

5. 请求转发
   发送脱敏后的请求到上游Provider

6. 响应拦截
   接收响应 → 检查是否需要恢复

7. 数据恢复
   For each 令牌:
     - 从隐私金库查询原始值
     - 替换响应内容

8. 响应返回
   返回恢复后的响应给客户端
```

### 5.3 核心数据结构

#### PIIMatch

```rust
struct PIIMatch {
    start: usize,       // 起始位置
    end: usize,        // 结束位置
    value: String,     // 匹配的原始值
    pii_type: PIIType, // PII类型
    confidence: f32,   // 置信度 (0.0-1.0)
}

enum PIIType {
    IdCard,       // 身份证
    Phone,        // 手机号
    Email,        // 邮箱
    ApiKey,       // API Key
    ApiSecret,    // API Secret
    AwsKey,       // AWS Key
    GithubToken,  // GitHub Token
}

enum RedactionStrategy {
    FPE,      // 格式保留加密 (可逆)
    Hash,     // 单向哈希 (不可逆)
    Replace,  // 直接替换 (不可逆)
    Mask,     // 部分掩码 (可逆)
}
```

#### PrivacyVault

```rust
struct PrivacyVault {
    // 会话级隔离
    sessions: HashMap<SessionId, SessionMappings>,
    // 加密密钥
    encryption_key: [u8; 32],
}

struct SessionMappings {
    mappings: Vec<(Token, OriginalValue)>,
    created_at: Instant,
    expires_at: Instant,
}
```

### 5.4 配置格式

```yaml
# config.yaml

# 服务配置
server:
  host: "127.0.0.1"      # 监听地址
  port: 8080             # 监听端口
  log_level: "info"      # 日志级别

  provider: "openai"      # 提供商
  base_url: "https://api.openai.com/v1"
  api_key: "${OPENAI_API_KEY}"  # 从环境变量读取

# PII检测配置
pii:
  # 启用的PII类型
  enabled:
    - id_card
    - phone
    - email
    - api_key
    - api_secret
    - aws_key
    - github_token
  
  # 脱敏策略
  strategies:
    id_card: "fpe"       # 身份证: 格式保留加密
    phone: "fpe"         # 手机号: 格式保留加密
    email: "replace"     # 邮箱: 替换
    api_key: "hash"      # API Key: 哈希
    api_secret: "hash"   # API Secret: 哈希
    aws_key: "hash"      # AWS Key: 哈希

  # 自定义模式
  custom_patterns:
    - name: "internal_key"

      strategy: "hash"
      enabled: true

# 隐私金库配置
vault:
  session_ttl: 3600      # 会话超时 (秒)
  max_sessions: 1000     # 最大会话数

fpe:
  key: "${FPE_KEY}"      # FPE加密密钥 (32字节)
```
