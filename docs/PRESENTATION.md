# 01 项目概述

## 背景问题

### LLM 应用的数据隐私挑战

- 用户发送给大模型的**原始敏感数据**可能泄露
- 身份证、手机号、邮箱等 **PII 信息**被第三方记录
- 企业合规要求（如 GDPR、个人信息保护法）
- API Key、数据库连接串等**商业机密**面临风险

## 解决方案

**Sec-Gateway** - 本地隐私保护代理

```
用户请求 → Sec-Gateway (本地) → LLM Provider
           ↓
        PII 脱敏
        本地存储
        响应恢复
```

**核心价值**：敏感数据不离开本地环境

# 02 核心功能

## PII 检测能力

### 支持 8 种敏感数据类型

| 类型 | 示例 | 检测方式 |
|------|------|---------|
| 🆔 中国身份证 | 110101199001011234 | Regex + 校验位验证 |
| 📱 手机号 | 13812345678 | Regex + 运营商号段 |
| 📧 邮箱 | user@example.com | Regex |
| 💳 信用卡 | 4532015112830366 | Luhn 算法 |
| 🔑 API Key | sk-proj-xxxxx | Regex + 熵检测 |
| 🌐 IP 地址 | 192.168.1.1 | Regex |
| 🔗 数据库连接 | mysql://user:pass@host:3306 | Regex |
| 🎫 JWT Token | eyJhbGciOiJIUzI1NiIs... | Regex + Base64 检测 |

---

## 脱敏策略

### 三种策略，灵活配置

**1. FPE 格式保留加密**（可逆）
```
原始: 13812345678
加密: 05509628502
解密: 13812345678 ✅
```

**2. SHA-256 哈希**（不可逆，用于日志）
```
原始: sk-proj-xxxxx
哈希: [HASH:e0b7453469e42b48]
```

**3. 占位符替换**（不可逆）
```
原始: user@example.com
替换: [REDACTED_EMAIL_001]
```

## 双 FPE 后端支持

### AES-256-FF1 vs SM4-128-FF1

| 特性 | AES-256-FF1 | SM4-128-FF1 |
|------|-------------|-------------|
| **标准** | NIST SP 800-38G | GB/T 32907-2016 |
| **密钥长度** | 32 bytes | 16 bytes |
| **性能** | ~15.7 µs/op | ~17.2 µs/op |
| **适用场景** | 国际项目 | 中国合规项目 |

### 运行时切换

```yaml
# config/default.yaml
crypto:
  fpe:
    backend: "aes"  # 或 "sm4"
```

```bash
FPE_BACKEND=sm4 cargo run
```

---

## 会话管理

### Vault 加密存储

- 每个会话独立加密
- 密钥 SHA256 派生
- 支持会话隔离
- 自动过期清理

### API 接口

```
GET  /sessions          # 列出所有会话
DELETE /sessions/:id    # 删除指定会话
```

## Vault 安全设计

### 多层保护

```
用户数据
   │
   ▼
┌─────────────┐
│  SHA-256    │  ← 密钥派生
│  派生密钥   │
└─────────────┘
   │
   ▼
┌─────────────┐
│   AES-256   │  ← Vault 加密
│   加密      │
└─────────────┘
   │
   ▼
本地存储（内存 HashMap）
   │
   ▼
会话隔离 · 零明文存储
```
