# Privacy Gateway - 工作计划 v1.0

## 1. 项目概述

**项目名称**: privacy-gateway  
**项目类型**: 本地代理Gateway (Rust + Axum)  
**核心目标**: 在终端用户和大模型之间建立一个隐私保护层，对敏感数据(PII)进行本地脱敏和处理，确保敏感数据只在本地流转，不泄露给第三方LLM提供商。

### 1.1 核心价值

| 价值主张 | 说明 |
|---------|------|
| **隐私保护** | 敏感数据本地处理，不上传原始数据 |
| **无缝兼容** | 对LLM Provider透明，不影响现有工作流 |
| **精确脱敏** | 高精度识别多种类型PII，低误报率 |
| **可逆恢复** | 脱敏数据可逆向恢复，不影响任务执行 |
| **可审计** | 完整的请求/响应日志，支持合规审计 |

### 1.2 差异化定位

| 差异化方向 | 竞争对手情况 | 我们优势 |
|-----------|------------|---------|
| 中国PII支持 | 竞品均无 | ✅ 身份证、手机号等 |
| API Key保护 | 仅有SentinelLLM | ✅ 更完整、更准确 |
| cc-switch集成 | 无竞争者 | ✅ 生态互补 |
| FPE可逆脱敏 | 大多数缺失 | ✅ 开箱即用 |
| 流式响应处理 | 大多数不支持 | ✅ 完整SSE支持 |

## 2. 技术架构

### 2.1 整体架构

```
┌─────────────────────────────────────────────────────────────────┐
│                         客户端应用                                │
│        (Claude Code / IDE / CLI / Claude.ai / Gemini CLI)       │
└────────────────────────────┬────────────────────────────────────┘
                             │ HTTP/HTTPS (localhost:8080)
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│                     Privacy Gateway (本地代理)                     │
│                                                                  │
│  ┌─────────────┐   ┌─────────────┐   ┌─────────────┐          │
│  │  请求拦截器   │──▶│  PII检测器   │──▶│  脱敏引擎    │          │
│  │ (Interceptor)│   │ (Detector)  │   │ (Redactor)  │          │
│  └─────────────┘   └─────────────┘   └─────────────┘          │
│         │                 │                  │                    │
│         │          ┌─────▼─────┐           │                    │
│         │          │  隐私金库   │           │                    │
│         │          │ (Vault)   │           │                    │
│         │          │ - 映射存储  │           │                    │
│         │          │ - 会话隔离  │           │                    │
│         │          └───────────┘           │                    │
│         │                                    │                    │
│  ┌──────┴──────┐   ┌─────────────┐   ┌─────▼─────┐            │
│  │  响应恢复    │◀──│  PII恢复    │◀──│  LLM响应  │            │
│  │ (Restorer)  │   │ (Reverser) │   │           │            │
│  └─────────────┘   └─────────────┘   └───────────┘            │
└────────────────────────────┬────────────────────────────────────┘
                             │ HTTPS
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│                    LLM Provider (远程)                          │
│              (OpenAI / Anthropic / Google / 本地LLM)            │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 核心组件

| 组件 | 职责 | 技术选型 |
|------|------|---------|
| **请求拦截器** | 拦截HTTP请求，解析JSON/流式数据 | Axum + tower |
| **PII检测器** | Regex + Entropy + NER多策略检测 | Rust Regex + tokenizer |
| **脱敏引擎** | FPE/令牌化/哈希/掩码 | aes-fpe + AES-GCM |
| **隐私金库** | 敏感数据映射存储，会话隔离 | 内存HashMap + AES加密 |
| **请求转发器** | 转发脱敏请求到上游Provider | Reqwest |
| **响应恢复器** | 解析响应，恢复脱敏数据 | Same Axum |

## 5. 技术选型

### 5.1 技术栈

| 组件 | 技术选型 | 理由 |
|------|---------|------|
| **语言** | Rust | 高性能、安全、内存管理 |
| **HTTP框架** | Axum | 异步、类型安全、tower集成 |
| **PII检测** | Regex + 自研Entropy | 快速、准确、无外部依赖 |
| **FPE** | aes-fpe (Rust) | NIST FF1兼容、纯Rust |
| **配置** | YAML (config-rs) | 易于编辑、广泛支持 |
| **日志** | tracing + tracing-subscriber | 结构化、高性能 |
| **测试** | Rust built-in + cargo test | 集成测试 |
| **加密** | aes-gcm (ring) | 现代、安全 |

### 5.2 性能目标

| 指标 | 目标 | 说明 |
|------|------|------|
| 无PII请求延迟 | <5ms | 透传开销 |
| 单PII检测+脱敏 | <10ms | 包括检测+脱敏 |
| 100个PII检测 | <50ms | 批量处理 |
| P99延迟 | <100ms | 包含网络开销 |
| 内存占用 | <50MB | 空闲状态 |
